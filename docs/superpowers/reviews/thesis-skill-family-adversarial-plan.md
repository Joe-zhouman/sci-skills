# Existence Audit — thesis-skill-family spec

**net: -20 lines deletable**

Findings tagged against `docs/superpowers/specs/thesis-skill-family.md`, read through the design lens (`~/.claude/agents/refs/aquarius-lens-design.md`) + glossary (`docs/superpowers/glossary.md`) + article-family source (`sci-skills-article/skills/`).

§Design Rationale ④ (L65): causal: "一个模式跑三尺度 = sci-write rung ladder（模块/章尺度）的升尺度复用" misattributes the pattern. sci-write's rung ladder (SKILL.md L238-242) maps FIGURE ROLES to a single-paper claim (fig1=1st rung, fig2=anchor, fig3=stakes) — it is not a "results→question→claim chain at module/chapter scale." The pattern does not exist in the cited source. The "thesis 家族不是发明新机制，是把已有纪律抬一阶" framing is false: the three-scale pattern is new. Rewrite as "new pattern, composed from rung-ladder's figure-to-claim shape + sci-story's gap→response shape."

§Design Rationale ① (L47) vs §Workflow gates (L141-142): contradiction: the enforcement split says "Architecture-level: 非机械，只能人工门控." But the spec's own gates are mechanical architecture-level checks — thesis-intro "每个 gap→某章填了," thesis-summary "共性 grounded 在具体章节 results" + "每个 gap 被 callback." Coverage and grounding ARE mechanical. The split should be: architecture-level DEPTH = human-gated; architecture-level COVERAGE/GROUNDING = mechanically checkable (and the spec already encodes these). The "architecture = human-only" overclaim hides half the enforcement the spec itself designs.

§Workflow thesis-polish (L148): contradiction: "AIGC 降率（带脚本，吃 PaperPass/PaperYY/知网报告，按伤不伤质量排序杠杆）" and "去 AI 味（不优化检测器特征）" cannot both hold. Reading detector reports + rewriting to lower scores IS detector-feature optimization (selectively, by the 不伤质量 levers). The "不承诺平台结果不篡改" parenthetical draws an integrity line, not a conceptual one. Pick one: either polish games detectors (AIGC降率, own it) or it de-AI-ifies prose style (去AI味, drop the detector-script). Collapsing wenqu-mem's three-way split (thesis-style / thesis-deai-review / aigc-reduce-playbook) into one skill produces the incoherence.

§Design Rationale ⑦ (L77, L183): framing: "thesis 比 article 简单——目的单一" is false by raw count (7 skills vs article's 6) and by content (thesis adds AIGC降率 / template-at-init / source-registry / spine / theory — none in article). The glossary itself (L19) names thesis's own 4-stage lifecycle (开题→中期→盲审→答辩). Serving 0 of those stages is a scope choice, not simplicity. Rewrite as "scoped to writing stage; lifecycle nodes out of scope for v1" — the layout decision (no spine folder) stands on its own, the "simpler" justification does not.

§Design Rationale ② (L57): causal: "拆解本身是强制捋清思路的机制…上一个没做好就不能进下一个…由文件交接面强制（dissect 读 spine.md，spine 没定就进行不下去）" slides from "done well" to "set/done." The file handoff enforces EXISTENCE of spine.md, not QUALITY. The gate (L139) is "三字段非空且人工确认" — existence + author-says-so. A hollow spine.md clears the gate; dissect proceeds on a bad main-line. Decoupling prevents carrying an ABSENT main-line, not a BAD one. The "防带病推进" claim overstates what file-handoff enforces; only the architecture-depth human gate (which the spec admits is unreliable-by-design) catches quality.

§Design Rationale ② (L51-57) vs glossary three-entry architecture (glossary L8-12): negative-space: glossary mandates the thick-orchestration entry as PERMANENT ("not a transitional form to be replaced… cheap models… are permanent too"). The thesis family has 6 execution + 1 init and NO orchestration entry. A cheap-model user must manually chain 6 skills. The spec's "no orchestrator" justification only addresses "don't bake orchestration into execution skills" (wenqu-mem's 21-skill single-entry form) — it conflates "no single-orchestrator skill" with "no orchestration entry." Either add a using-thesis-skills entry or state explicitly that the cheap-regime is out of scope and the strong-model-only entry is a deliberate v1 cut.

§Implementation Notes layout (L101-117) vs article layout (article-init SKILL.md L38-46): contradiction: thesis puts spine.md / terminology-ledger.md / thesis-sources.md at the TOP of the shared sci-skills/ namespace. The article family keeps NO top-level files in sci-skills/ (only README + subdirs); article's terminology-ledger lives at sci-skills/sci-write/terminology-ledger.md. In a shared workspace (the spec's own acceptance, L179: "article+thesis 共用工作区"), this yields TWO terminology ledgers — sci-skills/terminology-ledger.md (thesis) + sci-skills/sci-write/terminology-ledger.md (article) — for terminology that overlaps (the small papers ARE the thesis's source). The "no spine folder" decision creates the collision. Put thesis's shared files under sci-skills/thesis/ (a subdirectory, like every other skill's home) OR reuse article's ledger if the terms are shared.

§Workflow thesis-dissect (L140, L110-111): framing: the layout (thesis-dissect/paper-A/, paper-B/) + "逐篇拆+当场写 chN.tex" bakes in a 1:1 paper:chapter mapping. Theses that MERGE N papers into one chapter or SPLIT one paper across two chapters (both common in synthesis-heavy degrees) don't fit dissect's one-paper-one-chapter act. Unexamined constraint — no fallback for many:1 or 1:many paper:chapter mappings.

§Workflow thesis-theory (L143): yagni: "可重组对应正文章（标标记作者确认）" lets the theory skill MODIFY body chapters dissect already wrote — a cross-skill write that strains "read neighbors, don't orchestrate" (one skill rewriting another's on-disk output). And it's speculative: theory is written LAST (放最后), so body chapters are already done — "reorganizing" them is rework the author must re-audit. Inline: theory reads body chapters, writes its own chapter, flags overlaps into a list the author resolves manually. Cut the reorganize-body capability until a second caller exists.

§Implementation Notes (L116, sci-draw/): misfit: sci-draw is reused for "图片重组（按图仓库契约）." sci-draw is a DATA-DRIVEN drawing skill (makes new figures from data). "图片重组" — renumbering/re-cross-referencing figures from N papers into unified thesis numbering (Fig 3.1, 3.2) — is a different task no skill owns. Figure renumbering is cross-cutting (spans all chapters dissect writes). Either name the owner (dissect? typeset? polish?) or scope it out; "reuse sci-draw" is the wrong skill for a non-drawing task.

§Design Rationale ① (L41-49) + glossary Serves-the-author-first (L90-92): hidden assumption: the enforcement split's gate is "author decides," and Serves-the-author-first assumes the author CAN judge framework depth. But the glossary itself says AI must "point at cracks the author's attachment hides" — the cracks are where the author CANNOT see. If the author could evaluate the candidates, they wouldn't have the blindspot; if they can't, the gate passes hollow frameworks. The stance "not for novices" asserts the premise without verifying it. If author competence at architecture-level is inadequate (even for a non-novice — attachment is the blindspot, not skill level), the human gate is theater and the spec's core anti-pattern defense (pain 2) is undefended. The spec should name this as the load-bearing premise and state its failure mode.
