# Polish strategy — 语言服务论证：诊断分层与全稿纪律

每个 polish job 都打开本文件（SKILL.md Reference index 第一行）。它是执行参考的总纲：诊断的次序、论证与语言的关系、对前人与术语的纪律、学位论文特有的跨章一致性。章职能判据在 `references/chapter-guide.md`；语体层 AI 痕迹判据在 `references/chinese-register.md`；机械护栏在 `references/style-guardrails.md`；可用短语在 `references/phrasebank-zh.md`。

> **Provenance（内化来源，spec §⑦）**：`sci-skills-article/skills/sci-polish/references/writing-strategy.md` 移植 + 学位论文化。**移植**（语言中性部分）：core stance（语言服务论证）/ claim-evidence-boundary 三元 / 对前人工作的公允 / 术语一致性。**章化**：paper 级 section 职责 → 章级职能（chapter-guide.md）；hourglass 结构 → 章职能与末章 callback（学位论文的宽→窄→宽活在章间，不在节内）。**新增**（学位论文尺度）：跨章 voice 一致、诊断全稿先行（§⑥）。**丢弃**：英文例句、期刊摘要格式细节、productive writing order 的具体排序（写作顺序由写作链定，polish 侧只保留"写作顺序 ≠ 阅读顺序"的推论，§⑥）。

## ① 核心姿态：语言服务论证

润色不只是把句子改顺，它是把论证改得可读。一段话打磨得再漂亮，若仍在做错误的论证工作，这次编辑就是失败的。

- **语言服务论证。** 不润色句子的同时留下断裂的逻辑——先修逻辑，再修文字。
- **对读者有同理心。** 读者要先知道这与自己相关，才评估新颖性；先信任你，才复用你的方法。
- **不造数据、不造引用、不造机理、不造新颖性主张。**
- 稿子结构性粗糙时，先重构逻辑，再润色行文——这就是 §② 的分层为什么是脊柱。

错位的样子（文字已顺、论证工作错位）：

- 改写前（绪论里的一段）："实验结果表明，本文方法在三个数据集上的精度均优于基线，验证了方法的有效性。"——句子通顺，但这是结果段的句子出现在绪论：润色它的文字 = 精修一段本不该在这的话。先认出错位（章职能层），句子层无活可干。

## ② 诊断分层（本 skill 的脊柱）

诊断从上往下，修复从上往下，次序不跳（SKILL.md rule 1）：

```
章职能 → 段落结构（断缝）→ claim/evidence/boundary → 句子语体
```

- **上层坏，下层白做。** 章职能错的章（绪论写成教材、总结写成复述），句子改得再顺也是精修一栋歪楼——章职能坏 = 结构级 = surface 给作者（type-① commit message），polish 不动手。
- **绝不句子级润色结构级断裂的段落**（先结构后句子）。段落没有 controlling idea、模块 transition 缺失时，先缝合（分级：句级补写 / 结构级 surface，rule 3），再进语体层。
- **Stage A 是点名的例外**：AIGC 降率在结构诊断之前跑句级改写——报告定位必须新鲜（先做通用润色会把文本移走，报告对不上）；Step 1 只读不动，Step 2 逐句复检 Stage A 句子，例外在语体层闭环。判据与杠杆见 `references/aigc-playbook.md`。

各层判据索引：章职能 → `references/chapter-guide.md`；段落结构 / 断缝 → 缝合分级（SKILL.md rule 3）；三元 → 本文件 §③；语体 → `references/chinese-register.md`。

各层对照（诊断 → 修复动作，SKILL.md Step 1/2 的合读）：

| 层 | 诊断什么 | 坏了先做什么 |
|---|---|---|
| 章职能 | 这章的 job 对不对 | 结构级 → surface（type-① commit message） |
| 段落结构 / 断缝 | controlling idea、模块 transition | 句级缝 → 补写（grounding 按 rule 3）；结构级 → surface |
| claim/evidence/boundary | 三元齐不齐 | 标注 + 降档 / 补限定语——证据不动 |
| 句子语体 | AI 痕迹 / 翻译腔 / 术语漂移 | 按语体手册改写（chinese-register.md） |

次序为什么不可跳：**下层的修复会被上层修复作废**——结构修复会移动、删除文本，先润色的句子可能整段被砍；反过来，三元标注决定了句子层哪些词能改（降档）、哪些不能碰（数据）。从下往上改 = 每层返工一遍。

## ③ claim / evidence / boundary 三元

每个重要的科学陈述由三部分构成：**claim**（说了什么）、**evidence**（什么支撑它）、**boundary**（主张到哪里为止，还剩什么不确定性）。

典型失效（修复优先于节奏——先修三元，再管句子）：

| 失效 | 中文学位论文里的样子 |
|---|---|
| 有 claim 无 evidence | "本文方法显著优于现有方法"——全文找不到比对数据 |
| 有 evidence 无 claim | "图 3 显示提升了 12%"——然后呢？数据没有被论断收编 |
| 有推广无边界 | "该方法可广泛应用于各类实际场景"——哪些场景？为什么？ |
| 关联写成因果 | "X 与 Y 显著相关，因此 X 是 Y 的原因"——相关不是因果 |

polish 对三元的动作是**标注，不是改证据**：

- 证据撑不起的 claim → 降档（hedging 三档对表，`references/phrasebank-zh.md` §①）或 flag，绝不加码。
- 数据、统计量、引用一个不动（诚信线，`references/style-guardrails.md` §③；数字 typo 修正也要作者确认）。
- boundary 缺失 → 补的是限定语（"在本实验条件下""就所测样本而言"），不是新证据。

标注法：对每个重要陈述问三句——"说了什么（claim）？凭什么（evidence）？到哪为止（boundary）？"三问答齐，三元在位。

- 改写前（有 evidence 无 claim）：图 4 给出了不同温度下的转化率曲线。
- 改写后（claim 收编，中档动词）：转化率在 350 ℃ 以上趋于平台（图 4），提示温度不再是该阶段的控制因素。

boundary 最常丢的位置：各章小结与总结展望——那里 claim 最大、限定最少；polish 在这两处逐句查 boundary，缺了补限定语，不砍主张（砍主张是作者的决定）。

## ④ 对前人工作的公允

不靠压扁前人来立 gap。把已有工作写成弱基线来抬高自己，是盲审最容易抓的硬伤，也是智力上的不诚实。优先句式（中文对应）：

- "已有研究表明……，但其在……条件下的表现仍不清楚。"
- "前人工作确立了……，尚未解决的是……"
- "……方法在……任务中取得了良好效果；当面对……时，其有效性仍有待检验。"

三式共同点：**先承认前人做成了什么，再指明没做什么**——gap 立在"未覆盖"，不立在"做得差"。

- 改写前（压扁式）：现有检测方法精度低、速度慢，难以满足实际需求。
- 改写后（公允式）：现有方法在标准缺陷库上的精度已达 95% 以上[6-8]，但对跨尺度缺陷的漏检率仍在 10% 量级——本文针对后者。

配套纪律：

- "研究表明"必须有引用跟着（无引用的"研究表明"是硬伤——模糊归因，`references/chinese-register.md` §②）。
- 引用照抄原文主张，不升格：原文说"提示"，不能引成"证明"（引用纪律，SKILL.md pervasive discipline）。

## ⑤ 术语纪律（ledger）

- **一个概念一个术语，全稿一致。** 首次接触稿件即建/扩 `sci-skills/thesis-terminology-ledger.md`：列关键术语、缩写、单位、记号，每个概念定一个 canonical form，每章执行。
- **一致性 > 多样性。** 为"避免重复"而换同义词（该方法 → 所提方法 → 本方案 → 该框架）是清晰度的损失，不是文采——读者会怀疑你换了概念。这与语体层判据同源（`references/chinese-register.md` §①），与 AIGC L5 杠杆默认不用的理由也同一（`references/aigc-playbook.md` §②）。
- **缩写同一纪律**：首次出现给全称（中文名 + 英文缩写），此后全稿一种写法——正文叙述与图表标注统一，不与全称来回切换。
- polish 只 extend（`source: thesis-polish`）+ enforce（Step 3 全局统一，type-② commit）；不做 ad-hoc 章内改名——术语冲突记录后等 Step 3。

同义循环的样子：

- 改写前：本文方法……该方法……所提方法……本方案……（同一概念四种称呼）
- 改写后：全稿统一 ledger 的 canonical form（如"本文方法"）。

## ⑥ 学位论文尺度：跨章一致与全稿先行

**跨章 voice 一致。** 每章由不同 session 产出，天然带口音差：人称、时态习惯、谦抑强度、小结句式。polish 是全稿通读的唯一时机，也是统一 voice 的唯一时机：

- **人称**：全稿一套（"本文"为主干时，不冒出某章独立用"我们"指同一主体——除非学科惯例允许并用）。
- **谦抑强度**：同一类证据（如消融实验）在 ch2 用"表明"、在 ch4 用"或可归因"，就是跨章 voice 裂缝——按 §③ 对表统一。
- **小结句式**：一章的小结是"本章回答了……"、另一章是"本章首先介绍了……"，后者是复读失效（`references/chapter-guide.md` §正文章）。

人称裂缝的样子：

- 改写前：ch2 写"我们首先对样品进行了表面处理"，ch4 写"本文首先对样品进行表面处理"——同一类动作两种主语。
- 改写后：统一为主干人称；"我们"仅在学科惯例允许并用时出现，且全稿一致。

**写作顺序 ≠ 阅读顺序 → 改的顺序自由，诊断必须全稿先行。** 章可以按任意顺序修（type-① commit 按章落），但 Step 1 的诊断读的是全稿：跨章问题（callback 对不上 gap、术语漂移、voice 裂缝）在单章内看不见。先全稿诊断，再逐章修——顺序反了，每章都要返工。

**跨章 baton 保护**（改任何一章时）：

- 绪论的 gap 表述是 gap-map anchors——改写不丢锚点（`references/chapter-guide.md` §绪论）。
- 末章 callback 句对齐绪论表述；改了一头，另一头要复查。
- 章间递进句（上一章 results 引发下一章 question 的章级版本）与 `chapter-map.md` 的 progression 契约对齐。

**全稿先行 ≠ 全稿重写。** 诊断读全稿，修复仍逐章落（type-① commit）；跨章问题（术语统一、baton 对齐）集中走 Step 3 的 type-② commit，不夹在单章 commit 里。
