# Chapter guide — 章职能判据 + 缝合点（Step 1 第一层的对照表）

Step 1 章职能层诊断的对照表 + Step 2 修复优先级 + 各章缝合点。每章型四件事：**职能**（这章的 job）/ **润色优先级** / **常见失效** / **缝合点**（本章最容易断缝的位置与检查法）。诊断次序与三元纪律在 `references/polish-strategy.md`；失效的句子层修复在 `references/chinese-register.md`。

> **Provenance（内化来源，spec §⑦）**：`sci-skills-article/skills/sci-polish/references/section-guide.md` 章化 + 学位论文章型。**移植**：job / priorities / failure modes 三件套结构；绪论 positioning、摘要 mini-paper、总结选择性。**新增**（学位论文章型）：理论章（小论文没有的章型）、正文章 method-results 模块对与缝合点检查单（模块纪律源自 `sci-skills-thesis/skills/thesis-dissect/references/restructure-discipline.md`，polish 只消费其结构）、各章小结承接。**丢弃**：Title 节（学位论文题目不是 polish 的常规面）、英文 syntax 行（中文动词纪律并入各章型与 phrasebank）。

**总纪律先立：章职能坏 = 结构级 = surface，不修。** polish 永不重组章结构（SKILL.md rule 3/7）；本文件的职能判据用于**认出**失效、写进该章 type-① commit message，不是用于动手改结构。

用法：Step 1 拿职能判据认失效（认出 = 写进该章 type-① commit message）；Step 2 按润色优先级修句子层；缝合点节是各章的找缝入口——正文章的检查单是全稿缝合的核心面。

## 绪论 (ch0)

**职能**：positioning，不是教材。回答四问：已知什么 / 还有什么没解决 / 本文问什么 / 怎么答。综述为 gap 服务——每一节背景都收向问题。

四问在文中的落位（缺一 = 职能面缺项，surface）："已知什么"= 综述节；"没解决什么"= gap 节（显式命名）；"本文问什么"= 研究内容节；"怎么答"= 章安排。

**润色优先级**：

- 开篇段定位，不铺教材：背景知识只留立 gap 所需的最小集。
- 综述段按主题分组、每组收向一个 gap，不按年代流水记（"2001 年 A 提出……2015 年 B 提出……"是文献罗列，不是综述）。
- **gap 显式命名，不暗示——gap-map anchors 住在这章。** `sci-skills/thesis-intro/gap-map.md` 的每个 gap（`## Gap N`）在正文有对应表述（anchor）；**改写绝不丢锚点**：末章的逐 gap 收束、写作链的 callback 契约全靠它们（SKILL.md rule 7）。改写前后各数一遍：gap 数对得上、每个 gap 的表述仍可指认。
- "已知"到"本文做什么"的转折清晰（一两段完成，不长篇预告方法）。
- 不在此总结 Results / 总结章内容。
- 绪论的章安排 roadmap 句（"第 2 章建立……"）是学位论文惯例保留项——填充短语表的那条例外（`references/style-guardrails.md` §④）。

**常见失效**：

- 开篇读起来像教材章——背景铺陈收不到问题（句子层修复例见 `references/chinese-register.md` §⑦ 绪论 textbook 化）。
- gap 从不显式，读者要自己从背景里猜问题。
- 本文的问题被埋在背景段落中间。
- 方法细节长篇预告（属于正文章的内容）。

gap 显式命中的样子：

- 改写前（gap 靠暗示收场）：综上所述，表面缺陷检测仍有待进一步研究。
- 改写后（gap 点名）：现有方法对规则纹理背景下的微小缺陷漏检率高（gap-1），跨尺度缺陷缺乏统一表征（gap-2）——本文分别针对两者。

**缝合点**：

- **gap → 章安排的 handoff**：绪论末（研究内容 / 章安排）与各章的对应要对得上 `chapter-map.md` 的 role——绪论承诺了四章的事，正文章就得是四章；多承诺少交付或多交付少承诺都是断缝（结构级 → surface）。对账做法：把绪论承诺的每章一句话与 chapter-map 的 role 行并排，逐行能对上即 handoff 在位。
- **绪论 → 第一个正文章的递进**：第一个正文章的 question 由绪论的 gap 直接引发（模块链的起点）；这级 handoff 断了 = 全稿主线的第一处断缝。断的样子：第一个正文章开篇的 question 与绪论任何 gap 都对不上（凭空起问题）。

## 理论章 (ch1)

**职能**：理论地基——后面每个正文章都要踩的地板；统一框架实例化的叙述载体（`chapter-map.md` 的 framework-instantiation 在此章展开）。

**润色优先级**：

- 每个理论组件与框架的对应可指认：这个组件是什么、在统一框架里占哪个位置、后面的章怎么用——三问有一问答不上，组件就在裸放。
- 术语与记号的首次定义集中在此章定型（记为 / 称为 / 定义如式 (X)）；正文章直接沿用，不再重定义（ledger 纪律，`references/polish-strategy.md` §⑤）。
- 数学记号规范：同一量全稿同一记号；与正文章用法一致（跨章不一致 → Step 3 统一）。
- 地基深度以"后章要用的上限"为界——超出后续章节用到的理论深度是负重（读者带着用不上的理论上路）。

记号冲突的样子（polish 的高价值抓法——单章内看不见）：

- 改写前（跨章重定义）：ch1 定义 σ 为残余应力，ch3 又写"设 σ 为截面应力"——同一记号两个概念。
- 改写后：ch3 换记号（如 τ），或 ch1 首用即按全稿规划记号表（发现冲突 → 记录，Step 3 统一，不章内 ad-hoc 改）。

**常见失效**：

- **方法拼接，不是理论地基**——写成方法综述 / 工具罗列：每个组件都对，但收不到"后面的章为什么需要这些"。判别法：随机抽一个正文章的方法段，问"它踩的理论地板在哪节"——答不上就是拼接。
- 组件与正文用法脱节：理论章定义了 A，正文章用的是没定义过的 A'。
- 地基过深：与正文无关的理论铺陈——写了不用的理论，读者不知道为什么要读。

三问判别法示例：理论章 §2.3 给出多尺度特征分解——它实例化统一框架的"表征层组件"（占哪个位置），ch3 用它做缺陷定位、ch4 用它做跨尺度融合（后章怎么用）——三问齐，组件在位。若后续各章从未回头用它，它就是裸放的拼接物。

**缝合点**：

- **overlap 段（theory-map 清单）**：`sci-skills/thesis-theory/theory-map.md` 里未解决的理论-正文重叠段——polish 只**提醒作者**（写进 type-① commit message），**绝不动**（rule 3：theory 的 Overlap 清单先例，cross-edit 兄弟产物是禁区）。Overlap 条目长什么样：理论章 §2.2 与 ch3 §3.1 各写了一遍同一理论——未解决时两处表述可能漂移；polish 发现漂移只提醒，取舍是作者与写作链的事。
- **理论章 → 第一个正文章**：理论章小结交代"哪些组件就位"，第一个正文章开篇要接得住（用了哪个组件、为什么够用）。断的样子：正文章开篇用了理论章没定义的机制（地基缺一块），或全章不复引用理论章（地基没人踩）。

## 正文章 (ch2+)

**职能**：method-results 模块对。小论文的 IMRaD 在这里被重构为模块：method 紧跟对应 results（**配对，非序列**），每模块一个 **question→method→results 三元**（原子单元）；模块链起来：results → next question → next method → next results……一章 = 一串模块。（模块纪律全文见 `sci-skills-thesis/skills/thesis-dissect/references/restructure-discipline.md`——polish 消费其结构，不重写它。）

链条全貌：章节开篇 question → 模块 1（question→method→results）→ 模块 2 → … → 末模块 results 收口开篇 question。读者路径：每模块自足（问→做→答），不要求读者记住两节之前的 method 细节。

模块三元的样子（骨架）：

- question：§3.2 的单尺度特征漏检跨尺度缺陷——多尺度融合能否补上？
- method：为此构建并行三尺度分支（§3.1），在两个数据集上与单尺度基线比对（同数据同指标，表 4）。
- results：多尺度分支将跨尺度缺陷召回率提升 6.8 个百分点（表 4，p < 0.01），单尺度类缺陷不降。

**润色优先级**：

- 每模块三元完整：question（本模块答什么）/ method（为此做了什么——够复现）/ results（数据显示什么 + 引 figure/stat）。**列不出 question 的模块不该在这**——surface（缺模块或 question 错位，结构级）。
- results 报观察，不报解释：主结果用强档动词（表明 / 给出），趋势级用中档（提示 / 反映）；机理解释、文献对比不进模块正文（写作链纪律，polish 不添加——动词对表见 `references/phrasebank-zh.md` §①）。
- method 段拒含糊："按标准条件处理""采用常规方法"过不了复现测试——参数（浓度 / 温度 / 时长 / 样本量 / 测试名）逐字在位。缺参数 = surface（缺内容是结构级，polish 不编）。

  - 改写前（含糊 method）：样品经标准热处理后进行拉伸测试。
  - 改写后（可复现）：样品经 850 ℃ 保温 1 h 水淬（§2.2），在应变速率 10⁻³ s⁻¹ 下单轴拉伸，每组 3 个平行样。（数字从写作链产物逐字来——polish 不补参数。）

**常见失效**：

- 模块间无动机句——缝合点检查单全中，章读成方法合集。
- results 段内解释机理 / 对比文献（该在小结、总结层做的事进了模块正文）。

**缝合点（本 skill 的核心）**：模块间 transition——**上一模块 results 引发本模块 question 的那句动机**。模块链的逻辑钩子就这一句；缺了它，章读成方法合集。找缝检查单：

1. 模块开头是否直接跳进 method？（第一个词就是"采用 / 配制 / 设置"——缺 motivation 句）
2. 上个 results 与本模块 question 之间有没有"为什么做这个"？（读者能答"既然观察到 X，所以要查 Y"吗？）
3. 章节开篇 question 立住了吗？（module 1 的 question 来源——spine 的 role 落地）
4. 末模块的 results 回答了开篇 question 吗？（链条收口）
5. 下一模块是否复述了上一模块的 method / setup？（模块自足 ≠ 重复交代——复述句删）

找缝示例（检查单第 1、2 条命中）：

- 改写前（直接跳 method）：采用三因素四水平正交实验设计，因素水平见表 2。
- 改写后（补 motivation 句）：§2.3 的结果显示各单因素影响显著，但因素间的耦合作用未知——哪种耦合主导性能？为此采用三因素四水平正交实验设计，因素水平见表 2。

句级缺缝（缺一句动机 / 过渡）→ polish 补写，grounding 按粒度：`thesis-dissect/paper-*/trace.md`（模块级，先查）→ `chapter-map.md`（章级）→ spine（主线）；commit message 写明 grounding 文件（rule 3）。（trace.md 承载的正是缝粒度的地面：该模块的 claim + IMRaD 结构 + 如何推进主线——补 motivation 句前先读它，别凭正文现貌推断上一模块"应该"引发了什么。）

结构级断缝（模块顺序错 / method-results 配对错位 / 内容缺口）→ surface，不补写——补一句动机救不了错位的模块。结构级的样子：模块 3 的 method 其实在讲模块 2 该讲的表征（配对错位）；模块 4 的 results 用到模块 6 才建立的方法（前置依赖断）；两个模块各自独立、谁也不引发谁（question 链断）。

**各章小结：承接，不是复读。** 小结写两件事：本章回答了什么（对照绪论 gap / 本章开篇 question，点名证据）→ 遗留什么引出下章（下一章 question 的来源）。

- 改写前（第三遍方法叙述）：本章首先建立了表征模型，然后设计了实验方案，最后验证了模型的有效性。
- 改写后（承接）：本章确认了表面缺陷的可检测性下限（§2.4，表 3）；未覆盖的是跨尺度缺陷——下一章的多尺度特征正是针对它。

（同型失效的句子层判据在 `references/chinese-register.md` §⑦ 各章小结。本判据适用全部章型的小结：理论章小结交代"哪些组件就位"，正文章小结回答本章 question、引出下章。）

**paper-type 轻量并入**（章型论证侧重，章型看 `chapter-map.md` 的 role 行——写作链已定，polish 不改判，拿不准 surface 问作者）：

- **研究型章**（现象 / 问题驱动）：论证侧重"问题重要 + 设计能答它"——question 立得住、证据与问题对得齐，模块链沿"现象 → 追问"生长。
- **方法型章**（方法即贡献）：论证侧重"方法新 + 验证全"——capability gap 开篇、方法作为答案、基准上公平比对（同数据同指标）、失败 / 退化情形明说。
- 混装失效：方法型章写成领域综述开篇（该立 capability gap 的地方铺了背景综述）——surface 给作者，不静默改向。混装的样子：方法型章开篇半页领域背景综述，capability gap 迟迟不出现——读者以为在读研究型章。

## 总结展望 (末章)

**职能**：三件事——①工作总结：**逐 gap 收束**（callback 绪论每个 gap 的 promise；gap-map 的 callback-anchor 字段就是当时立下的诺言）②共性提炼：跨章共性 / 创新点归纳（提炼，不是并置）③展望：挂在 spine 的 Boundary 上落地。三块即 summary 产出的三节结构（工作总结 / 共性提炼 / 展望）——polish 按同序检查。

**润色优先级**：

- callback 显式：每个 gap 的收束读者能对上绪论（"gap-2 的问题在 §4.3 解决"式可指认）；gap 的表述与绪论 anchor 用词一致（跨章 baton：改了一头，复查另一头）。callback 显式的样子："针对 §1.3 提出的 gap-2（跨尺度缺陷缺乏统一表征），第 4 章的多尺度分支将其召回率提升了 6.8 个百分点（表 7）——该 gap 收束。"
- 共性是提炼：从各章结果抽出共享的机制 / 方法主线（"三章的共同基础是 X 机制"），不是把各章结论各抄一遍。
- 展望每项挂具体 boundary / limitation：从"适用范围限于…"落出 next question（短语见 `references/phrasebank-zh.md` §④；写作侧的展望 hook 属 summary，polish 复检同一标准）。
- 展望数量与 boundary 数量对齐：每个 boundary 至少被一个展望项接住——不接的要说明显式原因（为什么不做），不静默丢。

复述 vs 提炼：

- 改写前（复述）：第 2 章建立了 X 模型，第 3 章设计了 Y 方法，第 4 章验证了 Z 性能。
- 改写后（提炼）：三章共享同一条主线——以多尺度表征统一"检测—定位—评估"环节（X 是其表征层，Y 是其推理层，Z 是其验证面）。

**常见失效**：

- 各章结论复述——总结章写成各章小结的串讲（加了页数，没加信息）。
- 展望空洞："未来可进一步研究 / 推广到更多场景"（句子层修复见 `references/chinese-register.md` §⑦ 展望空洞）。
- 引入新数据 / 新主张（总结章不产新证据）。
- 漏 gap：绪论立了三个 gap，总结只收了两个——逐 gap 对账，漏了 = surface。
- 共性无证据兜底——"三章都体现了 X"，但没有任何一章的 results 直接支撑 X。

**缝合点**：

- **总结 ↔ 绪论的对账缝**：gap 数量、表述、解决状态逐一对上——全稿最大的一个跨章缝合点。
- **共性提炼 ↔ 各章小结**：共性段的主张必须每条都有某章证据兜底——提炼越线就是新主张。

## 摘要

**职能**：mini-thesis——背景 → gap → 方法 → 结果 → 意义，帮读者（与盲审）判断这篇论文相关、可信、重要。**中文摘要在 scope 内；英文摘要在 SKILL.md 的 scope cut 里明确排除**（作者自己的领地，polish 不碰）。

**润色优先级**：

- 背景一两句到位（标题已暗示的背景不再展开）；gap 与贡献各一句可定位；定量结果进摘要（"漏检率降至 3% 以下"优于"效果显著"）；末句说意义，不复读结果。
- 摘要是全稿的 mirror：术语按统一后的 ledger 复查（Step 3 之后回头再看摘要）。

定量进摘要的样子：

- 改写前：实验结果表明所提方法具有优异的性能与良好的泛化能力。
- 改写后：在两个公开数据集上，该方法将漏检率从 8.4% 降至 3.1%，跨数据集精度衰减小于 2 个百分点。（数字照正文逐字——摘要与正文对不上 = surface，不改数凑一致。）

**常见失效**：

- 背景淹没贡献（前三分之二是领域背景——句子层修复例见 `references/chinese-register.md` §⑦ 摘要背景淹没）。
- 结果罗列无综合（三个数字，没有一个收束句）。
- 末句空话（"具有广阔的应用前景"）。
- 摘要写了正文没有的主张（摘要越线 = 新主张，同样禁止）。

**缝合点**：

- **摘要 ↔ 全稿**：摘要里每个定量数字与正文一致（数字纪律——不改数据，对不上 = surface）；摘要的 gap / 贡献表述与绪论一致——读者从摘要进绪论，同一问题不该换说法（gap 措辞与术语双对齐）。
